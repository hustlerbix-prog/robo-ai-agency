2. BLOCKING ISSUE — DEMO_GUIDE Step 4 missing dependencies
====================================================================

DEMO_GUIDE Step 4 installs only:
    pip install faker fpdf2 PyPDF2 anthropic

But scripts/ingest_documents.py also imports:
    - requests      (NOT pulled in by anthropic, which uses httpx)
    - qdrant-client

Result: Step 8 (ingest into Qdrant) fails with ModuleNotFoundError
on a fresh machine.

FIX:
    pip install faker fpdf2 PyPDF2 anthropic requests qdrant-client

3. DOC-VS-CODE MISMATCHES — datasets are not what the docs claim
====================================================================

The stated theme is "a fictional Spanish-language medical clinic,"
but only IS-03 (the RAG corpus) is clinic-themed:

  IS-01  Docs say:  "Synthetic clinic emails"
         Code makes: Real-estate / property-management emails
                     (rental enquiries, viewing requests,
                     maintenance for APT-/LOC- property refs)
                     -> scripts/generate_is01_emails.py

  IS-04  Docs say:  "Patient intake forms"
         Code makes: LEGAL intake forms for a law firm (Civil,
                     Laboral, Penal, Comercial cases). Even
                     generate_all_demo_data.sh labels it
                     "legal intakes".
                     -> scripts/generate_is04_intakes.py

  IS-05  Docs say:  "Operations log" (clinic implied)
         Code makes: Trucking/freight operations log (Peru routes,
                     cargo types, drivers, freight USD)
                     -> scripts/generate_is05_operations.py

  AO-01  Docs say:  "LoRA fine-tuning training data" (clinic
                     implied)
         Code makes: Expense cost-code classification pairs
                     (MFG-MAT, LOG-FRT, ADM-OFF, IT-SFT, etc.)
                     -> scripts/generate_ao01_training_data.py

RECOMMENDATION: The headline RAG feature only uses IS-03, so fix
the docs (describe datasets honestly) rather than re-theming the
code — unless a single-scenario clinic demo is required.

4. SMALLER ISSUES
====================================================================

4.1  generate_all_demo_data.sh never runs generate_is03_chunked.py,
     uses the non-resumable generate_is03_procedures.py, and runs
     scripts in IS-01..IS-05 order while README/DEMO_GUIDE
     recommend fast-scripts-first. The two paths disagree.

4.2  README claims the IS-03 chunks (is03_chunks/section_*.json)
     are "the primary RAG corpus - ingested via
     ingest_documents.py". In reality ingest_documents.py only
     accepts a PDF and does its own 500-char chunking; the JSON
     chunk files are never ingested by anything (they exist only to
     make generation resumable). Doc wording should say the PDF is
     what gets ingested.

4.3  check_data_quality.py does not validate IS-04 at all, despite
     docs claiming it "validates all generated datasets."

4.4  ingest_documents.py crashes with IndexError (chunks[0] on an
     empty list) if the PDF has no extractable text. Add a guard
     with a clear error message.

4.5  Docker image naming is inconsistent across docs:
       - LAB_STATUS:  gerardk0/demo-rag:latest
       - DEMO_GUIDE:  docker.io/hustlerbixprog/robo-ai-agency:test_v1
       - compose:     local build only
     Pick one and align.

4.6  Dockerfile.rag copies scripts/ into the RAG image, but the
     image's requirements.txt lacks anthropic/faker/fpdf2, so those
     scripts cannot run inside the container. Dead weight; harmless.

4.7  .env.example includes unused GEMINI_API_KEY and
     OPENROUTER_API_KEY — nothing in the repo reads them.
